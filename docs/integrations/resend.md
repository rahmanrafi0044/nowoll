# Resend Integration Contract (email)

**Code:** `packages/email` — templates (React Email) + senders. **Checked against the official docs:** October 2026 (step 26).
**Docs:** https://resend.com/docs/api-reference/emails/send-email · https://resend.com/docs/send-with-smtp

## How Nowoll sends email

| Where | Sender | Goes to |
|---|---|---|
| Production | `ResendEmailSender` — Resend HTTP API | real inboxes |
| Development | `SmtpEmailSender` → **Mailpit** (`docker compose up -d mailpit`) | http://localhost:8025 only |
| Tests | `RecordingEmailSender` | memory |

`emailSenderFromEnv()` picks one. Development **always** uses Mailpit, even with a real key in `.env`
(unless `EMAIL_USE_RESEND=true`, set on purpose) — so a developer can never email real customers by accident.
Production refuses to start without a real `RESEND_API_KEY`.

Sending happens in the background workers (steps 27–28), never during a customer's request (CLAUDE.md §10).

## API used (official)

`POST https://api.resend.com/emails` · header `Authorization: Bearer <RESEND_API_KEY>`

| Field | We send |
|---|---|
| `from` | `EMAIL_FROM`, e.g. `Nowoll <orders@mail.nowoll.com>` |
| `to` | one recipient |
| `subject`, `html`, `text` | rendered template (HTML + plain text) |
| `reply_to` | the store's support address |
| `tags` | `[{ name: "type", value: "order-confirmation" }]` (letters, digits, `_`, `-`) |

Header **`Idempotency-Key`** (≤ 256 chars): the same key within 24 h is sent only once. The workers retry
failed jobs, so each email gets a stable key, e.g. `order-confirmation:NW-10001`.
Response: `{ id }`. 429 and 5xx → retry later; other 4xx → the email itself is wrong (logged, not retried).
The API key never appears in logs or error messages.

## Setup (Rafi)

1. **Account:** sign up at https://resend.com.
2. **Domain:** Domains → Add domain. Resend recommends a **subdomain** (keeps your main domain's reputation
   separate) — e.g. **`mail.nowoll.com`**. Resend then shows the exact DNS records (SPF, DKIM; optional
   DMARC) — add them **exactly as shown** at your domain/DNS provider and wait for "Verified".
3. **API key:** API Keys → Create (permission: sending access). Put it in `.env` as `RESEND_API_KEY`
   (and later in the production server's settings). Never commit it.
4. **`EMAIL_FROM`:** an address on the verified domain, e.g. `"Nowoll <orders@mail.nowoll.com>"`.

## Supabase password-reset emails through Resend

Supabase's built-in email only reaches members of your Supabase organization (2/hour). For real customers:

**Supabase → Authentication → SMTP Settings → Enable custom SMTP:**

| Field | Value (Resend's official SMTP) |
|---|---|
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | your Resend API key |
| Sender email | e.g. `orders@mail.nowoll.com` (on the verified domain) |
| Sender name | `Nowoll` |

**Reset email design:** Authentication → Email Templates → Reset Password → paste the HTML from
[`supabase-reset-password.html`](./supabase-reset-password.html) (generated by `pnpm email:preview`; a test
keeps it up to date). Its link is `{{ .RedirectTo }}?token_hash={{ .TokenHash }}&type=recovery` (supabase.md).

## The emails (packages/email/src/templates)

welcome · order confirmation (receipt) · payment confirmed · shipped (courier + tracking) · delivered ·
return approved (instructions) · return rejected (reason) · refund processed · newsletter confirm
(double opt-in, unsubscribe link) · low stock (to `EMAIL_ADMIN`) · password reset (Supabase).

Links: signed-in customers → their order page; guests → the order number + "Track your order"
(the private confirmation link is never put in an email — emails get forwarded).
Customer-typed text is escaped by React (never becomes HTML).

**See them:** `pnpm email:preview` → http://localhost:8025.
